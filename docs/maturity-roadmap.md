# 量化研究平台成熟度路线图

> 基线日期：2026-09-04。本文描述从当前本地监控框架走向“数据可追溯、回测可复现、风险可解释”的研究平台所需的质量门禁，不是功能愿望清单。

## 1. 定位与不可突破的边界

本项目只生成研究数据、研究组合和 `Signal`。`buy` / `sell` 只表示假设性研究信号，不是交易指令。所有阶段均禁止连接券商、创建或提交订单、自动下单、自动撤单以及任何绕过人工判断的执行路径。API 和页面不得使用“保证收益”“建议买入”等措辞。

路线图中的“可信”是指结果具备可审计的数据口径和可重复的计算过程，不代表结果适合使用真实资金，也不构成投资建议。平台继续默认只监听 `127.0.0.1`；如果将来改变监听范围，认证、TLS、访问控制和数据授权评估必须先完成。

## 2. 当前基线与可信度边界

### 2.1 本轮已经完成的基础能力

- [x] AShareHub 启动不再等待全量历史补齐：服务先可访问，日线在后台逐股补齐，支持断点续作、额度保留和进度展示。
- [x] 已区分 `/live`、`serving_ready` 和最低历史覆盖意义上的 `research_ready`，并在本地 API 与页面展示后台补数状态。
- [x] 已提供只读 SQLite、不会访问上游的日线质量审计，可发现缺口、重复、乱序、未来日期、历史覆盖不足和横截面共同日期不足。
- [x] 已有纯内存、无网络、无数据库副作用的日频回测内核；支持策略协议复用、次一会话开盘尝试成交、100 股整数手、佣金、滑点、卖出印花税、T+1、持仓和净值计算。
- [x] 回测可接收显式会话日历和逐证券交易约束；缺失成交、停牌或不可买卖可记录为跳过，不必伪造成交，并输出约束覆盖率、未验证成交和假设警告。
- [x] AShareHub 请求预算跨进程持久化；普通离线测试、质量审计和缓存只读接口不会自动消耗真实 API 额度。
- [x] API 密钥只允许来自进程环境或 Windows DPAPI 本机存储，不进入仓库、日志、公开配置、研究清单或浏览器。

### 2.2 这些能力目前不能证明什么

| 当前标记或能力 | 当前只证明 | 尚不能证明 |
| --- | --- | --- |
| `serving_ready=true` | 数据库和 HTTP 服务已可响应 | 数据完整、最新或可用于研究 |
| `research_ready=true` | 当前策略达到了最低历史条数覆盖 | 交易日历、复权、点时点股票池、公司行动和交易状态可靠 |
| 日线质量 `status=ok` | 在周一至周五兜底日历下通过结构检查 | 交易所节假日、个股停牌和供应商漏数已被正确区分 |
| `BacktestDiagnostics.decision_grade=false` | 当前运行只达到研究验证等级 | 尚未绑定官方、版本化且可验证的数据血缘，因此当前内核不会输出 `true` |
| 当前银行股票池 | 当前目录或 42 只静态兜底池可用于监控 | 任一历史日期当时真实可见的银行股集合 |
| 当前 AShareHub 日线 | 可获得未复权日频 OHLCV | 分红、送转、配股后的可比收益，或盘中/逐笔可成交信息 |

因此，当前 `decision_grade` 是保守的防误用门禁，不是平台级研究认证。默认的未复权行情、观察会话兜底和不完整交易状态会使结果保持非可信等级；即使调用方提供复权口径字符串、显式日历和完整约束，当前内核也固定返回 `false`。P0 必须在具备持久化证据后，才允许由血缘校验器自动计算该门禁，不能由调用方自我声明。

### 2.3 当前最主要的剩余风险

- 数据库已升为 `SCHEMA_VERSION = 3`，新增采集批次与 append-only `bar_observations`，不同来源、复权口径与修订可并存；旧 `bars` 仍作为兼容投影且唯一键未表达这些维度。
- v3 已分别持久化区间边界、`available_at`、`received_at`、落库时间和修订批次；现有 provider 尚无可验证发布时间与原生 revision，因此转换记录保守标为 `degraded`，API 与回测也尚未切换为 observation 权威读取。
- 市场状态和质量审计仍使用 `weekday_fallback`；它会把法定休市误报为缺口，也不能驱动真实的“下一交易会话”。
- 银行分类和证券目录不是 point-in-time 数据，回测会有幸存者偏差和分类回看偏差。
- 未复权日线没有公司行动及复权因子；“疑似除权缺口”只能抑制信号，不能恢复正确收益。
- 涨跌停、停牌、风险警示、上市初期等历史约束没有权威完整来源；缺少约束时的成交只能标为未验证。
- 回测结果尚无不可变的 run manifest 和输入 data hash，无法证明两次结果使用了完全相同的数据与规则。
- 当前没有完整的研究组合、基准归因、容量与流动性风险、压力测试以及 point-in-time 基本面。

## 3. 通用完成定义

一个路线图条目只有同时满足以下要求才可标为完成：

1. 数据契约、失败语义和版本规则已写入文档，缺失值保持 `None` 或显式状态，不能用 0 掩盖。
2. 实现具有确定性的离线单元测试、边界测试和至少一个跨层回放测试；pytest、CI 和应用启动不得自动调用收费 API。
3. 数据库变更通过正式迁移完成，旧数据库升级有夹具验证；不能仅修改 `CREATE TABLE IF NOT EXISTS`。
4. API 返回来源、口径、时间语义、质量和血缘；页面同时显示限制，不能只展示一个绿色“正常”。
5. 异常、缺数据、额度耗尽、中断恢复和供应商修订都有保守且可观察的行为。
6. 结果可以只凭持久化数据和 manifest 离线复现，不依赖当前网络、墙上时钟或可变目录。
7. 密钥、认证头和受限原始响应不进入日志、hash 明文、测试快照、前端或导出物。

## 4. P0：建立可信数据与可复现回测基线

P0 的退出目标不是“可以实盘”，而是：在指定历史时点，使用可验证的数据版本重放银行股研究策略，得到可复现、无明显未来函数、明确标注不可成交和数据缺陷的研究结果。

### P0.1 数据库迁移与不可变数据层

**为什么：** 后续时间血缘、复权和股票池都会改变表结构。没有迁移机制就无法安全升级现有用户的 SQLite，也无法审计修订。

**交付物：**

- 引入顺序迁移和 `schema_migrations(version, checksum, applied_at)`；每次迁移在事务内执行，并在不兼容升级前生成可识别的备份。
- 新表或 v2 表不覆盖原始记录。行情身份至少包含证券、周期、区间、来源、复权口径和供应商版本/修订身份。
- 增加采集批次、数据质量事件、交易日历版本、证券版本、股票池成员关系、公司行动、复权因子、交易状态和研究运行表。
- 新程序拒绝未知的更高 schema 版本；旧字段的兼容读取有明确废弃周期。

**可验证验收标准：**

- 使用包含现有所有表的 v1 夹具升级，旧记录数量、金额精度和时间戳不变；迁移后完整性检查通过。
- 同一数据库连续执行迁移两次，第二次无数据或 schema 变化；故意中断任一步骤后事务回滚，数据库仍可打开。
- 同一证券、同一交易日的不同 `source`、`adjustment` 或修订版本可并存，不会静默互相覆盖。
- 在 Windows 项目内 `.venv` 上执行迁移测试，全程不访问网络。

### P0.2 明确事件时间、可用时间和接收时间

**为什么：** 只有一个日线日期无法回答“策略在当时是否已经知道这条数据”。把交易日午夜或回填时间当成可用时间都会制造未来函数。

**交付物：**

- 日线契约增加 `session_date`、`period_start`、`period_end`、`available_at`、`received_at`、`persisted_at`、`source`、`batch_id`、`revision_id`、`quality_status` 和 `adjustment`。
- `available_at` 表示按数据发布语义最早可使用的时刻；`received_at` 表示本实例实际收到的时刻。历史回填的 `received_at` 不得冒充历史上的可用时刻。
- 证券分类、公司行动、财报和交易状态采用同样的 `effective_*` 与 `known_at` / `available_at` 双时间语义。
- 策略上下文只能读取 `available_at <= decision_at` 的记录；重放真实采集日志时还必须满足 `received_at <= decision_at`。

**可验证验收标准：**

- 一条 15:30 才可获得的收盘日线不能影响当日 15:00 的信号，可以影响下一允许决策时点。
- 晚到修订在修订可用前不可见；修改未来记录不会改变更早时点的信号和 data hash。
- 跨时区输入统一为 `Asia/Shanghai`，夏令时来源、无时区值和 `available_at < period_end` 等非法数据被拒绝或隔离。
- API 同时返回区间、可用、接收和持久化时间，不再用一个 `timestamp` 模糊表达四种含义。

### P0.3 官方、版本化的交易日历

**为什么：** 周一至周五不能识别节假日、临时休市和周末调休。错误日历会污染缺口判断、信号日、T+1 和下一开盘成交。

**交付物：**

- 建立按交易所和产品类型区分的会话表，记录交易日期、开闭市状态、各交易时段、发布时间、来源文档 hash 和日历版本。
- 导入上交所、深交所和需要时的北交所权威休市安排；临时通知以新版本追加，不能覆盖旧版本。
- 市场状态、补数计划、质量审计、指标窗口和回测共同依赖同一个 `TradingCalendar` 服务。
- `weekday_fallback` 只保留为明确降级模式；使用它的运行永远不能通过可信研究门禁。

**可验证验收标准：**

- 金样测试覆盖“工作日法定休市”“周末调休上班但不开市”“节前最后会话”“临时休市修订”和跨年边界。
- 周五信号在周一休市时只能进入下一个官方开市日；T+1 也按官方会话而非自然日计算。
- 每个研究运行固定引用一个日历版本；日历新版本不会悄悄改变旧运行结果。
- 质量审计在官方休市日不报告缺口，且能把市场休市、个股停牌和数据缺失区分开。

### P0.4 Point-in-time 证券主数据与银行股票池

**为什么：** 使用今天的上市银行名单回测过去，会遗漏退市、吸收合并或后来上市的股票，并把后来修订的行业分类泄漏到过去。

**交付物：**

- 建立版本化证券主数据和 `UniverseMembership`：包含上市/退市、证券类型、交易所、板块、风险警示、行业分类、`effective_from/to`、`known_at`、来源和版本。
- 银行股票池通过 `universe_at(session, knowledge_cutoff)` 查询；静态 42 只名单仅作为监控兜底，不能用于通过历史可信门禁。
- 每个回测会话保存当日可见的股票池快照 hash，并报告预期成员、有效数据成员和排除原因。

**可验证验收标准：**

- 在某历史日期查询不会包含其后上市的银行，会包含当时仍上市但今天已退市/合并的成员。
- 分类修订只能从其 `known_at` 起影响研究；增加未来成员不会改变历史信号。
- 横截面因子的分母来自当日股票池，而不是“最终有数据的幸存者”；成员缺数超过阈值时运行失败或降级，不能静默缩小样本。
- 股票池快照与来源版本进入 manifest 和 data hash。

### P0.5 公司行动、复权和总收益语义

**为什么：** 银行股分红频繁。未复权价格会把除息误认为下跌，也会低估持有期收益；启发式识别缺口不能替代公司行动。

**交付物：**

- 原始未复权行情只追加不覆盖；另存现金分红、送股、转增、拆并股、配股等公司行动及其公告日、生效日、修订时间和来源。
- 建立版本化复权因子，显式提供 `raw`、`qfq`、`hfq` 和总收益序列；返回基准日、因子版本和计算方法。
- 策略信号和收益统计必须声明价格口径；假设成交使用原始可成交价格，持仓账本按公司行动调整股份和现金。
- 公司行动修订使受影响的数据集、指标和研究运行失效，触发可追踪的重算，而不是覆盖旧结果。

**可验证验收标准：**

- 现金分红日不会在总收益序列中产生虚假暴跌，持仓现金收到相应红利；送转或拆股前后总价值在无市场变动时守恒。
- `raw` 数据 hash 在生成或更新复权序列后保持不变；任一公司行动修订会改变相应调整序列的 hash。
- 同一运行不能混用不同供应商或不同因子版本；API 对未声明 `adjustment` 的研究查询返回校验错误或使用有文档记录的保守默认。
- 除权除息日的涨跌幅基准使用权威参考价语义，不能简单取上一条收盘价。

### P0.6 历史交易状态与可成交约束

**为什么：** 有 OHLCV 不等于可以成交。停牌、涨跌停封单、风险警示、上市初期和价格取整都会使理想化成交严重偏高。

**交付物：**

- 按证券和会话保存停牌状态、可买/可卖、上下限价、参考价、风险警示、上市阶段、最小价位、每手股数、来源和规则版本。
- 回测只消费 point-in-time 约束，不按代码前缀猜涨跌幅；未知状态必须标为未知。
- 信号有效期、重试、过期和跳过原因是稳定领域模型；缺失下一开盘价时不能用收盘价代替。

**可验证验收标准：**

- 覆盖全天停牌、盘中临停、无成交、涨停不可买、跌停不可卖、无涨跌幅限制日、ST 状态变化和价格最小单位取整。
- T+1 阻止当日买入股份卖出，但允许卖出此前已结算股份；所有账本恒等式在费用后成立。
- 缺少约束的数据点不得产生“已验证成交”；可信运行要求约束覆盖率 100%，否则明确失败而不是仅给警告。
- 因下一开盘缺失而重试的信号在有效期结束后确定过期，不跨无限会话漂移。

### P0.7 Research run manifest 与 data hash

**为什么：** 只保存收益率无法回答“用了哪批数据、哪版规则和哪段策略代码”。没有 manifest 的结果不可复核。

**交付物：**

- 每次质量审计、因子计算和回测生成不可变 `ResearchRun` 与版本化 manifest。
- manifest 至少包含：查询区间、证券集合、输入记录 hash、来源/授权标识、日历版本、股票池版本、公司行动与复权因子版本、交易约束版本、策略名称和代码 hash、参数、引擎版本、费用/滑点/税费、随机种子、运行环境和所有降级假设。
- 对规范化、排序后的领域数据计算稳定 data hash；API Key、认证头、机器用户名和绝对路径不得进入 manifest。
- 结果、日志和导出物只引用 `run_id` / manifest hash；旧运行不可被原地修改。

**可验证验收标准：**

- 相同快照、代码、参数和引擎离线运行两次，manifest hash、交易序列和净值逐点一致。
- 改变任一输入记录、日历/股票池/复权版本、费用参数或策略代码，hash 必须变化。
- 在断网且不读取供应商当前目录的情况下，仅凭 manifest 指向的快照可复现结果。
- 自动敏感信息扫描证明 manifest、API 响应、日志和导出物不包含任何密钥。

### P0.8 回测内核、最低风险门禁与策略一致性

**为什么：** 当前内核提供了正确方向的成交骨架，但仍需让数据证据而非配置声明驱动可信度，并覆盖横截面和公司行动。

**交付物：**

- 实时研究和回测复用同一策略实现、指标定义和 point-in-time 上下文；禁止回测专用的未来数据入口。
- 将当前 `decision_grade` 加固为由数据集描述符和血缘校验器计算的只读结果，至少依赖 P0.2 至 P0.7 全部通过。
- 支持按官方会话定期再平衡、当日股票池、原始成交价、声明的信号价格口径、公司行动账本和逐日估值质量。
- 最低风险约束包括现金不得为负、禁止隐含杠杆、单票权重、组合集中度、成交量参与率上限和估值过期门禁；它们仍只是研究模拟约束。

**可验证验收标准：**

- 自动测试覆盖未来 K 线/未来成员不可见、周末与节假日、缺失开盘、停牌与涨跌停、T+1、整数手、价位取整、最低佣金、滑点、印花税和公司行动。
- 对每笔假设成交都能追溯到信号、可用数据、原始价格、交易状态和费用明细；无法证明可成交时必须跳过或使运行不可信。
- 净值恒等式、持仓成本、现金、成交额、换手和最大回撤由独立夹具逐日核对；缺失估值不允许伪造为 0 或悄悄沿用过期价格。
- 银行多因子策略在实时重放和回测中对同一知识截止时点产生相同信号；全套测试不访问真实 API。

### P0.9 数据作业、API 与页面可信度展示

**为什么：** 后台任务如果不可恢复，或页面把“服务已启动”显示成“研究已可信”，用户仍会被误导。

**交付物：**

- 将缓存查询和有副作用的上游补数彻底分开：`GET` 只读本地快照；补数、重算和回测通过显式异步作业创建，并支持幂等键、状态、取消、重试边界和断点续作。
- API 提供数据集、质量报告、作业、研究运行、manifest、交易/跳过记录和结果制品的版本化只读接口。
- 页面分别展示进程状态、采集状态、数据覆盖、研究门禁、日历/股票池/复权口径、约束覆盖率、run ID 和不可消除的限制提示。
- 增加数据健康页和回测详情页：净值、回撤、持仓、交易、未成交、费用、质量警告和输入血缘必须能相互追溯。

**可验证验收标准：**

- 对所有 `GET` 端点注入会报错的 provider，接口仍只读取本地数据，AShareHub 预算计数不变。
- 重复提交同一幂等键不会重复消耗额度；进程中断后作业从已提交的进度恢复，且不会留下“运行中”僵尸状态。
- API 契约测试覆盖无数据、部分数据、额度耗尽、质量失败和成功；Decimal、时间、枚举和缺失字段保持统一序列化。
- 浏览器测试确认 `serving_ready=true` 但数据未达标时仍显示醒目警告；任何 P0 门禁失败时均不能显示“可信研究已通过”。

### P0 退出标准

只有下面条件全部满足，P0 才完成：

- 一个固定银行股历史样本能够绑定官方日历、point-in-time 股票池、版本化公司行动/复权和完整交易状态。
- 每条输入具有明确的可用时间，回测通过无未来数据、T+1、不可成交和费用金样测试。
- v1 数据库可重复、安全地迁移，所有研究结果具有可离线复现的 manifest 和 data hash。
- API 和页面展示上述证据；任一证据缺失时自动降级，不允许用户用一个配置字符串绕过。
- 这些成果仍只是研究基础设施，不产生订单，也不构成真实资金决策依据。

## 5. P1：策略验证、研究组合与风险解释

P1 的目标是回答“该研究信号在样本外是否稳定、形成组合后承担了什么风险”，而不是提高页面上的单一分数。

### P1.1 Point-in-time 基本面与银行专属因子

**为什么：** 只用价格动量难以描述银行的资产质量、资本和盈利变化；直接使用最新财报又会产生公告日泄漏和修订偏差。

**交付物：**

- 基本面记录包含报告期、公告时间、首次可用时间、修订时间、合并口径、币种、单位、来源和版本。
- 在通用 PB、ROE、股息指标之外，定义银行适用的净息差、不良率、拨备覆盖率、核心一级资本充足率、成本收入比等字段及可比性规则。
- 因子计算只读取决策时点已公开的数据，记录滞后、缺失和异常值处理；缺失值不以 0 替代。

**可验证验收标准：**

- 财报公告前的回测看不到该报告；后续更正只在更正可用时点后生效。
- 单位、同比/期末值、单体/合并和会计口径不兼容时拒绝横向比较，并报告覆盖率。
- 每个因子值可追溯到原始字段、转换公式和输入版本；未来记录扰动不改变过去结果。

### P1.2 研究组合、基准与风险服务

**为什么：** 单票信号不能表达仓位、相关性、集中度、流动性和组合回撤，也无法判断收益来自市场还是策略。

**交付物：**

- 建立不可变的研究组合快照：目标权重、假设持仓、现金、净值、基准、调仓原因和 run ID；它不能转换成券商订单。
- 实现仓位/现金约束、行业与单票集中度、换手、成交量参与率、流动性、波动率、回撤、历史 VaR/CVaR 和情景压力指标。
- 增加相对银行指数或明确替代基准的超额收益、跟踪误差和收益/风险归因；基准也必须 point-in-time 且进入 manifest。

**可验证验收标准：**

- 任一时点 `现金 + 持仓市值 = NAV`，权重和为 1（允许显式现金）；约束失败会拒绝假设调仓并给出原因。
- 历史危机、利率冲击、信用损失和流动性折价等固定情景有可重复结果；风险数据不足时返回不可用而不是 0。
- 组合收益可分解为市场、因子、个股、费用和现金贡献，并能回到具体输入版本。
- 代码库中不存在券商 SDK、订单领域模型或外发执行端点。

### P1.3 样本外验证与研究纪律

**为什么：** 单次全样本回测容易过拟合。能解释过去不等于在未知样本中稳定。

**交付物：**

- 固定训练、验证、测试窗口，支持 walk-forward；测试集在参数冻结前不可用于调参。
- 报告基准对比、交易成本敏感性、参数敏感性、子时期/市场状态稳定性、换手、容量和因子衰减。
- 记录全部尝试的实验，而不只保留最优结果；对多重试验和筛选偏差给出警告。

**可验证验收标准：**

- manifest 明确数据切分和参数冻结时间；训练代码不能读取测试窗口指标。
- 关键结论在成本、滑点、延迟和参数邻域改变后仍有报告，不允许只展示最佳参数点。
- 报告同时展示失败实验、置信区间或重采样不确定性及最大回撤，禁止仅按收益率排名。

### P1.4 研究 API、UI 与可观察性

**交付物：**

- 增加研究运行比较、组合快照、风险、归因、基本面时间线和制品下载接口；长任务使用受控队列而非阻塞请求。
- 页面提供运行对比、样本内/外分隔、因子覆盖、风险暴露、压力测试和 manifest 查看器。
- 结构化日志包含 `collection_id`、`job_id`、`run_id`、阶段、耗时、缓存命中、解析丢弃和质量计数；指标与告警不包含证券数据授权外的信息。

**可验证验收标准：**

- 从任一页面数值可导航到 API 结果、run ID 和数据版本；切换运行不会混合缓存。
- 作业失败、重启恢复和配额延期可通过日志与状态接口定位，且日志均有上海时区时间戳和关联 ID。
- UI 在窄屏、空数据、部分失败和大结果集下仍可操作，研究警示始终可见。

### P1 退出标准

- 银行策略完成预先登记的样本外与 walk-forward 报告，所有结论均绑定 run manifest。
- 研究组合有基准、费用、归因和风险解释，缺失风险数据会阻止“通过”状态。
- point-in-time 财务因子不存在公告日泄漏，修订可追溯。
- 平台仍只提供研究输出，不连接或控制任何交易账户。

## 6. P2：工程运营、规模化与治理

P2 在 P0/P1 已可信后提升长期维护能力，不应通过堆叠数据源来绕过基础语义问题。

### P2.1 多源校验与规模化存储

**交付物：**

- 在授权允许的前提下，为关键数据引入第二来源核验；冲突按字段、时间和来源保留，不静默选最新值。
- 当有测量证据表明 SQLite 达到容量或并发边界后，再引入分区列式历史存储、元数据目录和单写者作业队列。
- 建立来源优先级、切换事件和重算策略；任何源切换都会改变数据版本和 manifest。

**验收：** 百万级/目标规模基准给出导入、查询、回测和备份恢复时间；故障切换不会把不同口径拼成同一序列，旧运行仍可复现。

### P2.2 持续集成与发布质量

**交付物：**

- 固定 Python 支持矩阵，加入格式、lint、类型检查、依赖与密钥扫描、覆盖率阈值、迁移测试和确定性回放测试。
- 版本化发布包、变更日志、API/schema 兼容政策和可验证依赖锁定；生产代码不得依赖测试时的网络。

**验收：** 干净 Windows 环境可从锁定依赖构建并通过全套离线测试；同一 release 的金样研究 hash 一致；破坏性 schema/API 改动会被 CI 拦截。

### P2.3 备份、恢复、SLO 与安全治理

**交付物：**

- SQLite/历史制品的一致性备份、保留、恢复演练和校验；定义数据恢复点与恢复时间目标。
- 为采集延迟、数据新鲜度、质量失败、配额、作业堆积和研究失败率定义 SLO、指标和告警。
- 如需非本机访问，先增加认证、TLS、最小权限、审计和限流；落实数据许可、留存、导出和删除政策。

**验收：** 定期从备份恢复到空目录并复现指定 run；密钥轮换不改变数据身份；未认证远程请求被拒绝；许可不允许的数据不能被导出或再分发。

### P2.4 研究治理与长期可维护性

**交付物：**

- 策略和数据集注册表、负责人、状态、变更审查、失效条件、弃用政策和模型卡。
- 监控“实盘外”的研究漂移：数据覆盖变化、因子分布变化、成本假设失效和历史结果不可复现。
- 提供只读研究归档和审计导出，不提供订单或券商集成插件。

**验收：** 任一已发布研究结论可定位到负责人、代码、数据、假设、风险和失效条件；被撤回版本在 UI/API 中不可再显示为有效。

### P2 退出标准

- 发布、迁移、备份恢复、监控和安全边界均有自动化证据与演练记录。
- 目标数据规模和故障场景下仍能复现 P0/P1 的金样研究运行。
- 数据使用符合来源授权；平台始终不包含自动下单路径。

## 7. 推荐实施顺序与依赖

```text
P0.1 数据库迁移
  └─ P0.2 时间与采集血缘
      ├─ P0.3 官方交易日历
      ├─ P0.4 point-in-time 股票池
      ├─ P0.5 公司行动与复权
      └─ P0.6 历史交易状态
           └─ P0.7 manifest / data hash
                └─ P0.8 回测与最低风险门禁
                     └─ P0.9 作业、API 与 UI
                          └─ P1 策略/组合/风险
                               └─ P2 运营与规模化
```

实施时应按这一依赖链提交小步、可迁移、可回放的变更。尤其不能先美化回测收益页面，再补交易日历、复权和股票池；那只会更有说服力地展示不可验证的结果。

## 8. 近期下一批可执行任务

1. 使用已建立的 v1→v2 迁移执行器，设计下一个时间/血缘业务表迁移。
2. 完成 v2 时间/血缘数据契约与往返测试，并与规范化 data hash 关联。
3. 定义 `TradingCalendar` 协议、版本表和离线官方日历夹具，将质量审计和回测从 `weekday_fallback` 迁到同一服务。
4. 定义 point-in-time 银行成员关系与查询 API，并为上市、退市、分类修订建立金样。
5. 在引入任何新策略参数前，先完成公司行动/复权和历史交易状态契约。
6. 将回测诊断从调用方声明升级为 manifest 证据校验，并确保默认 AShareHub 原始日线永远不能被误标为可信研究。

完成以上任务前，现有平台最准确的描述仍是“本地行情监控与研究验证骨架”。它可以帮助发现数据和策略问题，但不能提供经过生产级数据血缘验证的量化结论。
